# Infrastructure

Terraform and bootstrap automation for Azure AKS platform infrastructure.

## What This Sets Up
- Resource group consumed by Terraform (created by bootstrap script).
- Terraform remote state storage account and container (created by bootstrap script).
- VNet with AKS subnet and a dedicated future user VM subnet.
- AKS cluster with autoscaling default node pool.
- Azure Container Registry (ACR).
- Azure Key Vault (RBAC enabled).
- Data storage account (ADLS Gen2 enabled) with private containers.

## Prerequisites
- Azure CLI authenticated (`az login`).
- Terraform >= 1.6.
- A copied env file:
   - `cp infrastructure/bootstrap/.env.infrastructure.example infrastructure/bootstrap/.env.infrastructure`

## Run Order
1. Bootstrap Azure prerequisites:
   - `bash infrastructure/bootstrap/bootstrap_azure.sh`
2. Initialize, plan, and apply Terraform from terminal:
   - `cd infrastructure`
   - `source bootstrap/.env.infrastructure`
   - `bash bootstrap/bootstrap_azure.sh` (generates `terraform/backend.hcl`)
   - `cd terraform`
   - `terraform init -reconfigure -backend-config=backend.hcl`
   - `terraform fmt -check`
   - `terraform validate`
   - `terraform plan -out=tfplan`
   - `terraform apply tfplan`

## Backend Files
- `terraform/backend.tf` declares the backend type (`azurerm`) and is part of the Terraform source.
- `terraform/backend.hcl` is generated by `bootstrap/bootstrap_azure.sh` and contains backend values from `bootstrap/.env.infrastructure`.
- Use `terraform init -backend-config=backend.hcl` to pass those runtime backend values.

## Notes
- Start with `TF_VAR_private_cluster_enabled=false` for dev.
- Switch to `true` later to move toward private AKS API mode.
- The user VM subnet is created now for future secure access patterns; no VM/bastion resources are provisioned in v1.
- If Terraform reports `Backend configuration changed`, rerun `terraform init` using `-backend-config=backend.hcl`. If the backend location really changed, use `-migrate-state` instead of `-reconfigure`.
